Board 18 · jump to a terminal session

Today, opening a running Claude session that was started in a terminal says unavailable and prints claude --resume, which would start a second copy. Phase 18 brings that session's own Terminal or iTerm2 tab to the front instead. Its session record gives the process, the process gives its tty, and AppleScript selects the tab with that tty. Nothing has to be installed. Codex, tmux and Herdr stay out (owner, 2026-11-12). Pick one option in part 1. Rows are example data in the shape of real output.

Comparables

C1claudectl

Lists Claude sessions and jumps to their tab by tty with AppleScript, for Terminal.app and iTerm2. Works: no setup. Awkward: it jumps silently, and when the tab is gone you get an AppleScript error, not a reason.

C2Herdr sidebar

A multiplexer that owns every agent's terminal, so focusing a pane always works. Works: one keypress. Awkward: only for agents started inside it; it's a tool you have to adopt first.

C3tmux choose-tree

Shows every pane with a live preview, then switches to it. Works: you see where you're going before you go. Awkward: only inside tmux, and the preview costs screen space.

1 · How the jump shows

The same rule in all three places: the CLI (multi-link open), the TUI (Enter) and the Claude Code pane (row button). Each re-checks the tab right before it acts and never falls back to starting a second copy.

J1Jump straight

The action just goes. Afterwards the footer or CLI says where it went.

$ multi-link open 8f3e ✓ jumped to Terminal · window 2 · tab 3 (ttys004) pane, open row ● step-18-1 18.1 asked Do Step 18.1 in PLAN.md… Jump to terminal Copy id checked 1s ago · jumped to Terminal
GoodOne press, like Open in app. The same label everywhere.
WeakYou only learn which tab after the window has moved.

J2Say where first

Where the session runs is shown before you press: in the TUI's detail line, the pane's open row and open --dry-run.

$ multi-link open 8f3e --dry-run jump Terminal · window 2 · tab 3 (ttys004) pane, open row ● step-18-1 18.1 runs Terminal · ttys004 asked Do Step 18.1 in PLAN.md… Jump to terminal Copy id
GoodNo surprise jumps; like tmux's preview, in one line.
WeakOne more line in an open row; finding the window and tab costs a scan on every draw unless only the tty is shown.

States every option needs

unavailable · its tab is gone The process is still running, but no Terminal or iTerm2 tab has its tty (e.g. a closed window with a detached process). run: claude --resume 8f3e… (after it ends)
unavailable · runs in Ghostty Only Terminal and iTerm2 can be driven. Other terminals and tmux panes keep today's message.
blocked by macOS The first jump asks "allow … to control Terminal". If it was denied: System Settings → Privacy & Security → Automation.

Colours follow boards 16–17. iTerm2 is not installed on this Mac, so its path is covered by tests and stated as untested in the README unless it gets installed for the check. Lesson from Phase 17: macOS permission prompts (Automation, here) get their own README line and a state of their own.
