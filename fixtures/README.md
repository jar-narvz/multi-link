# fixtures

Test data for parsers, linking, state and step assignment.

## Two folders
- `fixtures/raw/` — real session files copied from `~/.claude` and `~/.codex`. **Git-ignored. Never commit.**
- `fixtures/` (everything else) — scrubbed copies, safe to publish.

## Scrubbing rules (raw → fixtures)
1. Replace real home paths with `/home/dev/` and repo names with stable placeholders (`repo-a` through `repo-d`, `repo-f`; `repo-e` is synthetic). Keep distinct directories distinct, including `Library/`.
2. Replace message and tool-output text with short placeholders (`"<prompt>"`, `"<stdout>"`),
   except the fields the code under test reads (command strings, ids, timestamps, event types).
3. Keep session/tool ids, timestamps and record structure exactly as they were; tests depend on them.
   Replace account identifiers (`creator_user_id`) with `user-dev`.
4. Redact real key shapes (`\bsk-[A-Za-z0-9_-]{20,}`), bearer tokens and named credentials;
   ordinary `task-*` values must remain intact.
5. Before committing, run:
   `rg -l "/Users/|\bsk-|api_key" fixtures --glob '!raw/**' --glob '!README.md'` — it must print nothing.

## Expected outputs
`fixtures/expected/{sessions,links,steps}.json` are written **by hand** from reading the raw sessions,
not generated by the code they test.

## Layout

`fixtures/sessions/` is a scrubbed home-shaped root for `--root fixtures/sessions`:

```text
sessions/
  .claude/projects/<encoded-cwd>/<session-id>.jsonl
  .claude/projects/<encoded-cwd>/<parent-id>/subagents/agent-<agent-id>.jsonl
  .claude/sessions/<pid>.json
  .codex/sessions/2026/10/29/rollout-<timestamp>-<session-id>.jsonl
  task-output/be01y5dv6.output
  repos/repo-a/{PLAN.md,PROGRESS.md}
  repos/repo-b/{PLAN.md,PROGRESS.md}
```

The raw sandbox checkouts map to `/home/dev/multi-link-sandbox/repo-a`,
`repo-a-wt`, and `repo-b`. Organic samples map to `/home/dev/repo-c` and
`/home/dev/repo-d`; a third organic checkout maps to `/home/dev/repo-f` and its subdirectories.
The synthetic malformed checkout uses `/home/dev/repo-e`. The local dashboard
checkout uses `/home/dev/project`; `~/Library/` remains `/home/dev/Library/`,
including its workspace suffix. Distinct raw directories retain distinct
scrubbed paths. Encoded project folder names match those scrubbed cwd values.
Temporary paths use `/tmp/dev/` and retain their tail, including task filenames. Remote URLs use
`https://example.invalid/repo-a.git`. Titles use `<name>`.

All source files, physical lines, line order, filenames, JSON keys and container
shapes are retained; only encoded project folder names change. IDs, timestamps,
epoch values, event discriminators, tool names, permission configuration and
session-record metadata stay unchanged, except `creator_user_id` becomes
`user-dev`. Paths are scrubbed. Prose, attachments,
API bodies, snapshots and output bodies use placeholders; signatures use
`<redacted>`. Bash launches retain command syntax; sandbox prompts retain their
`CASE-<name>:` marker followed by `<prompt>`. Organic commands are retained only
when a shell segment (split on `&&`, `;`,
`|` or newline outside quotes) starts with `codex` or
`node <path>/codex-companion.mjs`. Keep launch flags and `cd <dir> &&` prefixes,
scrub paths, replace quoted prompt arguments with `"<prompt>"` and heredoc
bodies with `<script>`. Other segments use `<command>`; commands with no launch
segment become `<command>` in full, including scripts and grep/ps/ls mentions.
Organic strings are at most 80 characters after accounting for placeholder
runs, IDs and paths.
Tool results retain the exact session/thread/turn ID lines and the sentence
naming background output, apart from paths; surrounding output prose uses
placeholders. The task-output banner/header is retained with a scrubbed workdir; other lines use `<stdout>`.

The copied background output lives at `task-output/be01y5dv6.output`; its named
runtime path is `/tmp/dev/<encoded-cwd>/<parent-id>/tasks/be01y5dv6.output`.
A fixture consumer must resolve that runtime task path to the copied task-output
file; this copy is not a claim that the original temp path exists.

Local regeneration and contract checks (scripts and originals remain ignored):

```sh
python3 fixtures/raw/scrub.py
python3 fixtures/raw/check-scrub.py
```

The checker compares corresponding records and nested fields, including session/tool ID
and timestamp values and the account-ID exception, rather than merely testing whether those values occur
somewhere in the destination. It also checks linking evidence, config, privacy,
file inventory, synthetic malformed lines and the ten ground-truth case rows.
Regression checks cover intact `task-*` values, key and bearer redaction, account
IDs, organic launch recognition and prompt/script removal, long organic strings,
and injective directory mapping (including cwd ancestors).
Use `--hidden` for an additional privacy scan: the ordinary `rg` commands do not
traverse the hidden harness directories by default.
